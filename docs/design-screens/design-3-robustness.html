健壮性：8 道闸 + 一条 fail-closed 原则

健壮性不是"写得小心"，是每个组件缺失/失败时都有预先定义好的降级行为。右下角那张降级表比任何代码都重要。

#机制硬约束
1幂等写 action 必须声明 keyFields；Idempotency-Key 重复必须返回首次结果，绝不重复副作用
2saga 补偿reversible=false 的 action 不许出现在多步 plan 的非末位（否则无法回滚）
3超时 + 熔断每 action 声明 timeout；模块连错 N 次即熔断，能力发现里标 unavailable，不许对着坏模块狂重试
4对账日切比对「审计里的声称 diff」vs「模块终态」；差异即冻结该 agent 写权限并告警
5审计不可变append-only + prevHash 哈希链，可验证未被篡改；大对象只存 inputHash
6双层授权控制平面拒一次 + 模块侧再拒一次；webhook HMAC + 时间戳防重放
7版本演进只增不删；未知字段必须忽略；一致性测试进 CI 做门禁
8降级见右表 —— 全部 fail-closed
组件缺失时的行为（fail-closed）
没有前端 SDK丢 Intent 帧，业务正确
没有 dry-run标 unverified → 强制审批
策略服务不可用默认 deny（不是 auto）
没有 LLM事件积压可重放，不丢
模块超时/熔断从能力清单摘掉
事件重复投递幂等键吸收
审计写失败先写审计再执行（WAL 风格）

可行性结论与风险登记

结论：技术可行。关键原语在 dsh 里都有现成对应（skill / jobs / token-meter / otel / session 持久化 / approval / permission / MCP 客户端 / api gateway / client UI 插件），真正要自研的是协议契约 + 治理平面 + 一致性套件，量级 4–6 人周可到 v1。最大的风险不是技术，是退化成规则引擎。

风险影响缓解
R1 退化成规则引擎高反模式判据 + demo 里零胶水代码，CI 检查有没有 handler 注册
R2 协议过抽象变空泛标准高只服务一个纵切面；每条规范必须有一致性测试用例，否则删掉
R3 真实系统没有补偿接口中risk.reversible 声明 + 不可逆强制审批 + dry-run 必读
R4 审计不可信（agent 自证）中模块侧独立记录 + 日切对账 + 哈希链
R5 共驾帧落地成本高中先只做 demo 页 + SDK hook，未接入降级为纯对话
R6 绑定 dsh 版本低协议层不 import dsh，只在 adapter 包依赖
